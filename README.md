## 📧 이메일 읽는 법

| 표시 | 의미 |

## 🧠 어떻게 골라내나요 (쉽게 설명)

사람이 매일 하나하나 읽는 대신, 아래 규칙으로 자동 판단합니다.

1. **관련 키워드가 있으면 점수를 줍니다** — "위성영상", "드론", "공간정보", "AI 분석" 같은 다비오 핵심 분야 단어가 제목에 있으면 점수가 올라갑니다.
2. **명백히 무관한 건 바로 걸러냅니다** — 제조, 공사, 청소, 급식, 서버·하드웨어 단순 구매처럼 다비오 업무가 아닌 게 확실한 공고는 점수 계산도 안 하고 바로 제외합니다.
3. **애매한 건 조건부로 살립니다** — "유지보수", "구매", "설치" 같은 단어가 있으면 원칙적으로는 제외 대상이지만, 핵심 키워드가 같이 여러 개 있으면 감점만 하고 살려둡니다 (실수로 놓치는 걸 방지).
4. **거래 이력이 있는 기관이면 가산점** — 항우연, 국토지리정보원, 방위사업청처럼 다비오와 거래한 적 있는 기관이 발주하면 점수를 더 줍니다.
5. **최종적으로 점수·조건에 따라 등급을 매깁니다** — 점수가 충분히 높고 "위성/드론/공간정보" 같은 핵심 조건까지 맞으면 '상', 그보다 낮으면 '중', 기준 미달이면 리포트에서 아예 제외됩니다.

즉, 정해진 규칙(사람이 미리 짜둔 조건표)을 따라 기계적으로 판단하는 방식이고, AI가 매번 새로 "판단"하는 게 아니라 항상 같은 기준으로 일관되게 걸러줍니다.

## 💡 자주 묻는 질문

**Q. 매일 몇 건이나 오나요?**
> 그날 기준으로 통과된 '상'/'중' 등급 공고 **전체**가 옵니다. 그중 어제까지 없던 새 공고에만 🆕 배지가 붙습니다.

**Q. 이미 마감된 공고도 오나요?**
> 아니요, 발송 시점 기준으로 아직 참가/입찰 등록이 마감되지 않은 '진행 중'인 공고만 옵니다.

**Q. 단순 제조/공사/물품 구매는 왜 안 보이나요?**
> 다비오 업무와 무관한 걸로 판단해서 자동으로 걸러내기 때문입니다. (위 "어떻게 골라내나요" 참고)

**Q. 국방전자조달(D2B) 공고는 버튼 눌러도 바로 안 들어가져요.**
> 국방전자조달 시스템 자체의 보안 정책 때문에 외부에서 상세페이지로 직접 연결이 안 됩니다. 메일에 있는 공고번호를 복사해서 D2B 홈페이지 검색창에 붙여넣으시면 됩니다.

**Q. 지금 당장 오늘자 리포트를 다시 받고 싶어요.**
> GitHub 저장소 상단 **Actions** 탭 → 워크플로우 선택 → **Run workflow** 버튼을 누르면 1~2분 뒤 메일이 옵니다.

- **G2B 자동 실행이 가끔 타임아웃으로 실패합니다.** 국내 네트워크에서는 나라장터 API가 정상 응답하지만, 자동 실행 서버(해외 클라우드)에서는 연결이 막히는 경우가 확인됐습니다. 재실행하면 될 때도 있고, 반복되면 서버 위치를 국내로 바꾸는 등의 조치가 필요합니다.

# 🛠 개발자/유지보수용 상세 문서

*이 아래부터는 코드를 직접 수정하거나 운영하는 사람을 위한 기술 문서입니다. 사용자 입장에서는 안 읽으셔도 됩니다.*

## 파일 구성 및 역할

실제로 GitHub Actions가 실행하는 진입점은 `dabeeo_bid_master.py`가 아니라 **`g2b_bot_email.py`**입니다.

| 파일 | 역할 |
| --- | --- |
| **`dabeeo_bid_master.py`** | 핵심 로직 라이브러리. 직접 실행되지 않고 `import`되어 사용됩니다. 전역 설정(`RECEIVERS`, `KEYWORDS`), 스코어링 엔진(`calculate_score`), G2B/D2B API 수집(`fetch_g2b_bids`, `fetch_d2b_bids`), SQLite 상태 저장(`init_db`, `save_bids_to_db`, `filter_new_bids`)을 담당합니다. |
| **`g2b_bot_email.py`** | 실행 진입점. GitHub Actions가 매일 실제로 실행(`python g2b_bot_email.py`)하는 파일입니다. 마스터 모듈에서 데이터를 가져와 HTML 이메일을 조립·발송하고, 신규 공고만 DB에 저장합니다. |
| **`test_scoring.py`** | 스코어링 회귀 테스트. 라벨링된 실제/가상 공고 제목으로 `calculate_score()`의 판정이 흔들리지 않는지 검증합니다. CI에서 본 실행 전에 자체 테스트로 먼저 돌아갑니다. |
| **`requirements.txt`** | 의존 패키지: `requests`, `urllib3`. |
| **`.github/workflows/daily_brief.yml`** | GitHub Actions 크론 설정. 스케줄, 시크릿 주입, DB 캐시, 실행 순서(테스트 → 본 실행)를 정의합니다. |

> ⚠️ `dabeeo_bid_master.py`는 라이브러리이므로 `python dabeeo_bid_master.py`로 직접 실행하지 마세요. 항상 `python g2b_bot_email.py`로 실행합니다.

## 스코어링 엔진 (`calculate_score`) 상세

1. **L0 정규화** — 띄어쓰기/전각문자 표준화.
2. **L1 범위 판정** — 공모전, 기업 모집, RFI/LTA/RFQ 등은 즉시 `제외`.
3. **L2 하드 제외** — 제조·공사·청소·급식·서버 납품 등을 정규식으로 즉시 차단 (기관명 오탐 방지 lookaround 포함).
4. **L2b 소프트 제외 + 구제** — '유지보수/구매/설치' 등은 원칙적으로 제외하되, 도메인 핵심 키워드가 2개 이상 겹치면 감점(`SOFT_EXCLUDE_PENALTY = -25`)으로 구제.
5. **L2c 감점** — 감리(-35), 타당성조사(-10) 등 스코프 밖이지만 하드킬은 과한 항목.
6. **L3 동형이의어 가드** — '위성TV', '학습지도' 등 오탐 방지.
7. **L4 가산** — 브랜드(다비오/어스아이 등, +40) > 코어(위성영상 등, +35) > 미드 > 인접 > 약가중 순.
8. **L5 동시출현 보너스** — 도메인 코어 × 기술 키워드 동시 출현 시 +20.
9. **L6 컨텍스트** — 발주기관 화이트리스트 +15, 추정가격 하한 미달 감점, 참가자격 미보유 항목은 감점 없이 플래그만.
10. **L7 허들 + 등급 매핑**

### 등급 기준 (`SCORE_HIGH_CUT=50`, `SCORE_MID_CUT=35`, `SCORE_LOW_CUT=20`)

| 등급 | 조건 |
| --- | --- |
| 상 | 50점 이상 **AND** 허들 키워드 통과 **AND** 도메인 강신호(동시출현 보너스 또는 도메인 코어 2개 이상) |
| 중 | 35~50점, 또는 50점 이상이나 허들·강신호 조건 미충족 |
| 하 | 20~35점 (약한 신호 하나 정도만 매칭 — 메일 하단 접힌 목록으로만 표시) |
| 제외 | 20점 미만, 하드 제외 키워드 검출, 범위 밖, 소프트 제외 구제 실패 |

> `SCORE_MID_CUT`을 20→35로 올린 건, "연구"처럼 흔한 약가중 키워드 하나 + 발주기관 화이트리스트(+15)만으로 무관한 공고(예: 활주로 재포장 연구)가 '중'에 섞여 들어오는 걸 막기 위함입니다. 대신 완전히 버리진 않고 '하'로 강등해 하단 접힌 목록에 보존합니다.

## 데이터 수집

**G2B**: `fetch_g2b_bids()`가 나라장터 입찰공고정보서비스(`getBidPblancListInfoServcPPSSrch`)를 시드 키워드(`KEYWORDS`, 18개)별로 개별 질의합니다 (기본 `days=3`). 키워드마다 순차 호출 + 최대 10페이지라 호출 수가 많습니다(최대 180회).

**D2B**: `fetch_d2b_bids()`가 공공데이터포털 "방위사업청_군수품조달정보 입찰공고_GW"의 `getDmstcCmpetBidPblancList`를 사용합니다. 키워드 반복 질의 대신 공고일자(`anmtDateBegin/End`) 구간으로 1~5페이지만 조회한 뒤 `calculate_score()`로 클라이언트단에서 필터링합니다 (개발계정 일일 트래픽 100건 한도 보호). 인증키는 `D2B_API_KEY` 시크릿을 사용합니다. 상세페이지 링크가 없어 공고번호(`g2bPblancNo`-차수 우선, 없으면 `dcsNo`)를 표시해 홈페이지 검색을 유도합니다. 국외/시설/공개수의 등 나머지 오퍼레이션은 미연동.

## 커스터마이징 가이드

핵심 설정과 규칙은 전부 `dabeeo_bid_master.py`의 `1. 시스템 통합 글로벌 설정` / `2. 다비오 고도화 스코어링` 영역에 있습니다.

* **수신자 변경**: 코드가 아니라 GitHub Secrets의 `RECEIVER_EMAIL`(콤마 구분)에서 읽습니다. → `Settings > Secrets and variables > Actions`에서 수정.
* **제외 단어 추가**: `NEGATIVE_KEYWORDS`(하드 제외) 또는 `SOFT_EXCLUDE_KEYWORDS`(구제 가능 제외)에 정규식 추가.
* **가중치 키워드 수정**: `BRAND_WEIGHT_KEYWORDS`, `HIGH_WEIGHT_KEYWORDS`, `MID_WEIGHT_KEYWORDS`, `ADJACENT_KEYWORDS`, `WEAK_KEYWORDS`. API 검색 시드는 `KEYWORDS`.
* **발주기관/참가자격 항목 추가**: `AGENCY_WHITELIST`, `ELIGIBILITY_PATTERNS`.

수정 후 반드시 `python test_scoring.py`로 회귀 테스트를 돌려 기존 판정이 깨지지 않았는지 확인하세요.

## 실행 및 운영

### 자동 실행
GitHub Actions가 평일 KST 08:30에 자동 실행합니다 (`.github/workflows/daily_brief.yml`). 순서: `test_scoring.py`(자체 테스트) → `g2b_bot_email.py`(본 실행). 중복 발송 방지용 SQLite 상태 파일은 Actions 캐시로 런 간 유지됩니다.

### 수동 실행
Actions 탭 → **Daily Satellite Bid Briefing** 워크플로우 → **Run workflow**.

### Secrets 설정
`Settings > Secrets and variables > Actions`:

| Secret | 용도 |
| --- | --- |
| `G2B_API_KEY` | 나라장터 입찰공고정보서비스 API 인증키 |
| `D2B_API_KEY` | 방위사업청_군수품조달정보 입찰공고_GW API 인증키 |
| `SMTP_USER` | 발송용 GMAIL 주소 |
| `SMTP_PASSWORD` | GMAIL 앱 비밀번호(16자리) |
| `RECEIVER_EMAIL` | 수신자 이메일(콤마 구분) |

### 로컬 실행
```bash
pip install -r requirements.txt
export G2B_API_KEY=... D2B_API_KEY=...
export SMTP_USER=... SMTP_PASSWORD=... RECEIVER_EMAIL=...
python test_scoring.py     # 회귀 테스트
python g2b_bot_email.py    # 본 실행
```
